# Raindrop Desktop：本地优先、远端接入与订阅同步

状态：已按用户授权完成独立架构审核，按分阶段结果实施；不是已实现功能清单。

## 审核结论与首阶段边界

- 本地进程内核心、原生阅读器、多远端账户隔离可以先实现，不开监听端口。
- Raindrop 0.7 的 CRUD 不具备订阅配置修订号、一致快照、删除墓碑与操作幂等回执。
  `state_revision` 是阅读状态修订，禁止用作订阅配置同步修订。
- 首阶段提供显式远端导入和「推送新增订阅（兼容模式）」；仅发送 Feed URL。
  不自动 PATCH、DELETE 或复制阅读状态，不将兼容模式称为完整单向或双向镜像。
- POST 前持久化 Unknown；结果未知时只读取远端核对，找不到也不自动再次 POST，
  防止远端删除后被复活。用户可以取消未知任务，不以普通重试隐藏风险。
- 相同 URL 复用本地源，但按服务地址和用户身份保留独立映射；不跨服务器自动转发。
  已存在的本地标题、分类、排序不覆盖，远端分类按来源隔离。本地删除后抑制重新导入。
- AI Provider 接口只返回元数据，不含密钥；AI 配置单独导入用于参考。
  未实现远端文章身份与执行授权前不运行远端 AI，不自动切换本地 Provider。
- 以下完整同步协议是后续里程碑，不是兼容版已经提供的能力。

## 已确认的目标

- 应用名、可执行文件和发布附件前缀为 `raindrop-desktop`。
- 使用 Rust NSH、NSH Design Guides 和平台原生交互，不套 WebView。
- 本地无需部署服务端即可运行，同时支持添加远端 Raindrop 服务器。
- 添加远端后，将当前用户有权访问的订阅列表和 AI 配置拉入本地。
- 本地新增订阅可选择单向或双向同步。
- 桌面 tag 独立使用 `raindrop-desktop-v*`，不得触发服务端 Docker 发布。
- 功能目标向 Web 对齐；开发中的原型不能被描述为已经与 Web 功能一致。

## 模块边界

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| local-core | 本地数据库、订阅、抓取、正文清洗、阅读状态、后台任务 | 现有 Raindrop Rust 核心 |
| native-reader | 原生导航、订阅队列、文章、设置与错误恢复 | local-core |
| remote-connections | 远端身份、能力协商、订阅与 Provider 元数据读取 | local-core |
| subscription-sync | 初始导入、映射、变更记录、离线队列、冲突处理 | local-core、remote-connections |
| ai-bindings | 远端 AI 引用和本地 Provider 配置的明确区分 | local-core、remote-connections |
| desktop-delivery | 分平台验证、独立版本、安装包、截图与文档 | 上述已验收模块 |

模块表是职责划分，不是已获批准的数据库或协议迁移方案。

## 本地运行

1. 首次启动直接进入本地工作区，不要求网址、账号、Docker 或常驻服务。
2. 进程内复用核心服务和数据库迁移，不复制 Feed、安全清洗或 AI 实现。
3. 使用 OS 应用数据目录下的独立 SQLite；不得打开或改写用户已有的服务端数据库。
4. 不为本地 UI 启动公网或回环 HTTP 监听端口。UI 到核心使用类型化进程内调用。
5. 抓取和存储在后台执行，UI 不等待阻塞 I/O；进程退出时停止任务并释放数据库。
6. 同一数据目录只允许一个写入实例。崩溃后能恢复已提交的数据和待同步任务。
7. 没有网络时仍能阅读已缓存正文、管理本地订阅和保存待同步变更；新内容抓取和远端 AI 必须明确显示网络依赖。

## 远端连接与首次导入

- 在原生「设置 → 服务器」添加多个连接，显示名称、地址、用户、连接状态与上次同步时间。
- 验证 TLS，拒绝 URL 内账号密码和跨源重定向泄露凭据；本机开发允许 loopback HTTP。
- 登录后协商版本与同步能力。当前 0.7.0 的订阅 CRUD 不等于完整的双向同步协议。
- 首次列出待导入订阅与可用 AI 配置，用户确认后写入本地；分页必须完整读取后才提交同步检查点。
- 首次导入不向远端写回本地存量，不隐式覆盖同名对象。对同一 Feed 的重复导入必须幂等。
- 远端对象按连接、服务端实例身份、认证用户 ID、对象 ID 隔离；更换账号不可复用旧队列或映射。
- 移除连接默认仅断开并撤销能够撤销的远端会话，保留导入本地的订阅；删除本地副本是另外的明确操作。

## 订阅同步语义（拟定默认值）

| 模式 | 远端 → 本地 | 本地 → 远端 |
| --- | --- | --- |
| 仅本地 | 不参与 | 不参与 |
| 单向拉取 | 接收新增和修改 | 不写回 |
| 单向推送 | 首次按用户确认导入，此后不自动覆盖本地修改 | 推送用户明确选中的新增和修改 |
| 双向 | 接收新增和修改 | 推送新增和修改 |

- 单向必须显示箭头和文字，不使用含糊的「同步」开关。
- 新连接建议默认「单向拉取」；本地新增订阅默认「仅本地」，可选择目标连接和方向。
- 同步设置按连接保存；订阅可覆盖连接默认规则。可同步到多个远端，但每个远端独立排队和授权。
- 首版同步范围为订阅存在性、Feed 地址、标题覆盖、分类及订阅顺序。分类 ID 也需要来源映射，不得直接复制远端数据库 ID。
- 暂不将文章正文、已读、收藏、用户账号、MCP token、插件可执行文件或任意本地文件默认为跨端同步对象。
  本地保留 Web 的相关功能，与这些数据是否跨端同步是两个不同的承诺。
- Feed 身份规范化复用核心规则；不能擅自删除 URL 查询参数、认证信息或合并语义不同的 Feed。

### 删除与冲突

- 建议默认不传播删除，特别是不因断网、鉴权失败、分页缺失或远端清空而清空本地。
- 用户主动启用「同步取消订阅」后，删除以带版本的 tombstone 同步，不以列表中缺失推断。
- 初次启用删除传播、切换方向和补推积压变更前显示影响预览；更换方向不会回放之前未授权的写入。
- 使用共同基线做三方比较。只有一边变更时应用该边；两边改不同字段可合并；同一字段冲突保留双方版本待用户选择。
- 修改与删除并发时暂停该对象的自动同步，不按设备时间自动决定胜负。
- 重试不得重复创建订阅或覆盖并发修改；禁止用“最新时间戳获胜”掩盖时钟漂移。

### 持久化与协议边界

- 需要独立的远端连接、对象映射、共同基线、待发送 outbox、已应用操作和删除记录。
- 本地修改与 outbox 入队必须在同一事务提交。网络请求不占用数据库事务或 UI 锁。
- 远端成功后在本地原子更新映射与检查点；若远端已成功而本地确认前崩溃，通过幂等操作 ID 安全重试。
- 服务端需要可协商的变更游标、对象修订、删除记录、乐观并发前置条件和幂等写入支持。
  具体接口及迁移另行设计；不得把尚不存在的 API 当成可调用接口。
- 对不具备这些能力的旧版服务端，只允许明确标识的导入/只读拉取，不伪装成可靠双向同步。
- 首次完整拉取完成前、游标失效或服务器身份变化后，不得据此发送删除。
- 每个远端单独限流、退避和暂停；遇到 401 停止并要求重新认证，不无限重试。
- 普通数据库和日志不保存明文密码、会话或 Provider 密钥。持久登录必须接入 OS 凭据存储；不可用时明确要求重新登录。

## AI 配置边界

现有 `/api/v1/ai/providers` 返回 Provider 元数据、模型、策略和修订，不返回凭据。
用户对远端共享 Provider 的读取权限不等于导出管理员 API key 的权限。

- 可以拉取当前用户可见的 Provider 名称、接口类型、模型、启用状态、策略等授权元数据。
- 远端 Provider 保存为带服务器来源的引用，不将其伪装成已具备本地凭据的 Provider。
- 默认通过远端执行 AI，密钥继续保留在远端；断开远端或离线时不能显示为仍可运行。
- 既有远端任务接口依赖远端文章身份。未在远端存在的本地文章不能直接套用远端 ID：
  必须先具备合法映射，或在服务端提供受权限、配额与正文上传同意约束的执行能力后才能处理。
- 本地独立调用 AI 需要用户另行配置自己的密钥，或未来经过明确授权的安全凭据迁移流程。
  不新增默认明文密钥导出接口，不复制远端密钥密文到本地冒充可用凭据。
- 拉取 AI 配置默认单向、按来源隔离；不自动覆盖本地 Provider，不默认反向修改远端管理配置。

## 原生界面与交互

- Linux、macOS、Windows 为桌面目标；本次不扩展 Mobile、Web、TUI。
- 原生窗口、菜单、焦点、文本输入、系统字体；三栏阅读、可调分隔、独立滚动。
- 工作区始终以本地数据为主；服务器是来源和同步目标，不强制用户在多个孤立阅读器间切换。
- 「服务器」中清楚呈现同步方向、待同步数量、错误恢复及冲突处理；不常驻巨大成功横幅。
- 新增订阅时默认只问 Feed 地址，展开「同步到…」后选择目标和方向；未登录或无写权限的目标说明原因。
- 文章阅读、收藏、已读等高频操作维持安静紧凑；状态和键盘可见，不靠 hover 暴露唯一操作。
- 主题只从 `desktop/theme.json` 读取语义 token；复用 app-owned styled controls，不在页面拼接原始颜色。
- 长集合使用 NSH virtual list，按业务 ID 保持身份；行复用、离屏跳转和筛选后选择都需要测试。

## 功能对齐与非目标

最终按 Web 的用户流程建立逐项验收表：订阅和分类、OPML、阅读与搜索、已读和收藏、
阅读偏好、AI Provider、AI 文章处理与翻译、插件和 MCP、备份与恢复、相应账号与设置。
其中部署型多用户/数据库管理只在合适的远端管理上下文出现，不硬塞给本地个人阅读器。
任何尚未原生实现的流程必须标注，不把“可在浏览器打开”算作原生功能已交付。

同步不等于备份，不是通用数据库复制；不同步账号密码、MCP token 或整个服务器配置。
不为桌面标签构建 Docker，不修改 vendor，不迁移服务端现有数据库到桌面目录。

## 工程约定

- `desktop/` 是独立 Cargo workspace，与服务端版本隔离；NSH 各 crate 固定到同一已核验版本。
- `desktop/src/` 放原生 root、store、UI、连接和本地核心适配；`desktop/tests/` 放集成测试。
- 同步协议的服务端改动在现有服务端模块与迁移体系中实现，单独验证向后兼容。
- Rust 名称、错误类型和风格延续现有代码。UI 读取变化值时使用绑定闭包，不保存初次渲染快照。

```rust
text(move || state.with(|reader| reader.pending_sync_count.to_string()))
```

预计验证入口（实现后作为验收命令，不代表当前已通过）：

```sh
cargo fmt --manifest-path desktop/Cargo.toml -- --check
cargo check --manifest-path desktop/Cargo.toml --all-targets --locked
cargo clippy --manifest-path desktop/Cargo.toml --all-targets --locked -- -D warnings
cargo test --manifest-path desktop/Cargo.toml --locked
cd desktop && nsh check && nsh test && nsh run
```

## 验收场景

1. 没有服务端、Docker 或远端账号时首次启动可添加 Feed、抓取、阅读、收藏；重启后数据保留。
2. 添加远端后导入全部分页订阅；重复导入不重复；同名跨账号对象不串数据。
3. 本地新增订阅在推送和双向模式下正确出现在所选远端，在仅拉取/仅本地模式下不上传。
4. 远端新增或修改在拉取/双向模式到达本地；推送模式不会覆盖本地变化。
5. 断网后本地修改可落盘，重启恢复队列；“远端提交成功、客户端未确认”后重试仍只产生一个对象。
6. 同字段并发修改、删除与修改冲突、游标过期、429、会话过期都可恢复，不静默丢失内容。
7. 默认删除不传播；显式开启后通过修订和 tombstone 处理，错误列表不触发删除。
8. AI 元数据可导入，凭据不泄露；无本地密钥时不能显示为本地 AI 可用；远端执行前正确说明数据发送范围。
9. 本地退出时后台任务停止、数据库可安全重开；多实例不会并发迁移。
10. NSH headless 覆盖交互、回收、焦点和状态；Linux 真窗口视觉检查，macOS/Windows 云构建与独立视觉验收。
11. Web 行为保持兼容，服务端同步迁移有回归测试；桌面 tag 不触发服务端发布和 Docker 工作流。

## 待确认的产品默认值

- 新连接默认只拉取，本地新订阅默认仅本地，首次导入不推送本地存量。
- 删除默认不传播；并发同字段冲突人工选择，不静默覆盖。
- AI 默认保存远端引用并在远端执行，不自动复制密钥。
- 此次同步先覆盖订阅和 AI 元数据；文章正文、已读、收藏的跨端同步不默认包含。

以上默认值确认后，再拆实施计划、确定协议/数据库迁移并实现；规格本身不授权直接发布未完成的桌面版本。
