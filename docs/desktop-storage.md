# Desktop 存储与恢复边界

本设计采用 `ddia-principles`：优先明确事实来源、事务边界和部分失败，
不把 HTTP 成功、进程锁或本地事务误认为跨设备的一致性协议。

## 事实来源与存储选择

- 本地文章、订阅、分类、阅读状态的事实来源是应用私有目录里的 SQLite。
  复用现有核心模型与迁移，不另外维护一套桌面订阅业务规则。
- 远端仍是独立事实来源；导入不是数据库复制，不建立分布式事务，
  不用本机时间戳或最后写入获胜覆盖远端/本地修改。
- 本地文件数据库使用 WAL、外键检查、单写连接和 5 秒锁等待。
  **桌面端显式启用 `synchronous=FULL`**；这项策略也会用于重连后的连接。
  服务端默认保持原来的 NORMAL，避免桌面功能改变服务端性能策略。
- FULL 保证建立在 SQLite、操作系统与磁盘正确遵守同步请求的前提上；
  它不是备份，也不能抵御整个设备丢失或恶意/故障磁盘控制器。
- 应用数据目录只允许当前用户访问，同一资料库用 OS 文件锁限制一个桌面实例。
  这是本机访问边界，不是跨机器 fencing token，不能通过共享盘多实例部署。

## 同步记录为何先用有界文档

`desktop_sync_state` 是独立于文章热路径的低频配置/发送意图快照，
单行、单条 SQL 原子替换，包含 schema 版本、远端配置、来源映射、抑制和发送意图。
导入提交前还保存待绑定的 `(profile, feed hash)` 来源，防止核心提交但映射未保存时丢失退订语义。
每次读取与写入均受限于 8 MiB；最多 32 个连接、20,000 个意图。
所有读改写路径在同一进程内由共享互斥锁串行化，避免丢失更新。
远端密码、Cookie、CSRF 和 Provider API 密钥不进入文档。

这一选择牺牲局部更新与数据库外键约束，换取初期清晰、可审计的原子快照。
不能将它扩展为文章事件日志或无限增长 outbox：若连接/任务量增长，
应迁移到规范化的 profile/link/intent/suppression 表，增加唯一键、外键与状态索引，
用版本化迁移保证已有 Unknown 意图和来源抑制不丢失。
达到当前上限时拒绝新写入，不能静默截断、清空或丢弃历史任务。

版本未知或文档损坏时保留原记录，禁用远端操作；本地资料库仍可打开阅读。
不能为了“启动成功”重置记录，否则会丢失未知发送状态并复活远端删除。

## 外观与语言

`desktop_preferences` 与同步文档分离，单行保存 schema 版本、语言和主题。
读取时校验版本及枚举；保存用单条 SQL 原子更新，不会出现只保存语言而丢失主题的中间状态。
界面串行提交设置，在 FULL 提交成功后才切换，失败仍保留上一次显示及持久化值。
不支持的版本或损坏值不会被默认设置覆盖；本地阅读继续使用默认外观，远端同步记录不受影响。
设置无需远端连接，且不会上传至服务器。

## 导入与退订事务

1. 在本地写事务之外完整读取远端订阅、分类和可见 AI 配置，验证游标、身份与 URL。
   旧 API 的分页不是一致快照，因此不从列表缺失推断远端删除。
   订阅分页整体受限于 256 页、20,000 条、32 MiB、60 秒和 4096 字节游标；
   每个网络请求再按剩余总时间与字节预算收紧，不允许空页持续换游标无限请求。
2. 使用共享核心的 OPML 导入命令，而不是循环调用公共 HTTP 写接口。
   全批次订阅、分类、标题和初始排序在同一个本地事务里提交，保留核心业务配额。
   已存在的本地订阅不覆盖，分类名按来源确定性隔离。
3. 核心事务之前 FULL 提交待绑定来源，再导入；成功后用一次写入保存映射并清除待绑定标记。
   此处不冒充跨模块原子事务：若核心提交后、最终映射保存前崩溃，订阅元数据已完整提交，
   待绑定来源仍在。可以重新导入补齐映射，也可以先退订：按本地 Feed hash 将待绑定来源
   变为抑制记录，不会在下次导入时复活。待绑定记录最多 20,000 条，超限拒绝导入。
4. 本地退订先持久化所有来源映射、待绑定来源和发送意图对应的抑制，再删除订阅。
   已成功远端写入、但响应丢失且尚无来源映射的 Unknown 意图也必须纳入抑制。
   若删除失败，保留本地订阅；不删除远端。

不会在数据库事务里等待网络。当前同步互斥锁可能覆盖网络请求，
只串行化低频同步管理，不占用 SQLite 写锁，也不阻塞本地阅读查询。

## 发送状态与安全取舍

`Ready → Unknown（FULL 提交）→ 网络 POST → Confirmed（提交）`。
POST 只包含用户明确选中的 Feed URL，不自动转发另一来源导入的订阅。

- 崩溃发生在发送前：仍可能留下 Unknown；宁可要求核对，不冒险猜测未发送。
- 服务端已提交、响应丢失：保留 Unknown；再次执行只读取远端列表寻找同 URL。
- 远端不存在该 URL：保持 Unknown，**不自动再次 POST**，避免复活用户远端的删除。
- 权限拒绝或限流：保留可操作状态，等待用户显式再操作；无自动重试循环。
- 用户取消意图：不撤销已经发生的远端写入，也不宣称远端已回滚。

这是一项偏向 safety 而非自动恢复 liveness 的兼容方案，不保证 exactly-once。
可靠双向同步必须先提供稳定实例身份、一致快照/变更游标、配置修订、删除墓碑、
条件写入及与业务变更原子提交的幂等回执，并覆盖所有 Web/OPML/级联删除路径。

## 已验证及未验证

自动测试覆盖单实例锁、重启持久化、FULL 模式、100 条导入、元数据保留、
SQL 触发器注入失败后的全事务回滚、核心提交后缺失映射的恢复、
响应丢失后禁止重发、Unknown 尚无映射时退订不复活，以及同步记录损坏后的本地阅读。
还覆盖映射保存失败后重启并先退订的恢复顺序、恶意分页预算，以及设置保存失败/未知版本保留。
真实断电/磁盘故障及 macOS、Windows 平台行为仍需对应环境验证，不能由单元测试推定。
