# 数据库维护

管理员可以在「设置 → 数据库」查看 SQLite 主文件、WAL、空闲页、文章与订阅源总数，以及各表连同索引的占用。使用未编译 dbstat 的 SQLite 时，仍显示基础统计。侧栏数字是当前账户的未读数，不是实例文章总数。

## 刷新记录

刷新记录和当前未被消费的刷新事件保留 7 天。后台每小时检查，按每批 100 条清理；有积压时继续安排短间隔批次。近期记录、活跃任务、已被领取或重试的事件、未知事件类型不会被删除。Feed 删除后遗留的过期闲置事件也会被回收。

这是运行诊断记录的保留策略，不会删除文章或用户阅读状态。SQLite 会复用释放的页面，但不会自动缩小主文件。

## 可选文章清理

默认关闭，升级不会启用。管理员开启后，可设置保留 1–3650 天（默认 30 天）。后台每小时检查并分批删除超过存入时间的已读文章，仅适用于 SQLite。

- 所有可见订阅者都已读，且没有任何用户收藏或显式标为未读的文章，才可删除。
- 带 AI 任务/处理记录的文章保留。
- 文章删除不可撤销；保留小型身份标记，防止下次 RSS 刷新重新导入同一篇文章。
- 开启或缩短保留期需要在界面确认；关闭只停止后续清理，不恢复文章。

## 压缩

「压缩数据库」先分批清理全部过期刷新记录，再执行 SQLite VACUUM，最后尝试截断 WAL。此操作本身不清理文章；文章删除由上面的独立开关控制。

HTTP 请求返回 202 后任务在后台继续运行，关闭设置不取消任务；再次打开可查看状态。读请求使用独立只读连接。批次间释放写连接；VACUUM 仍需独占写连接，写入可能短暂等待。为避免长时间阻塞，可选 WAL 截断不会等待持有快照的读者，此时界面会提示稍后回收 WAL。需要额外可用磁盘空间，最多约数据库大小的两倍。空间统计使用实际文件大小，不把尚未归还的逻辑页误算成已释放空间。

重启后后台任务状态不保留；SQLite 保证文件一致性。清理分批提交，失败后可重试。保留设置和去重标记持久化。

## 本次问题证据

一份 545.43 MiB 的数据库中有 12,060 篇文章，而非侧栏显示的约 1,600 条未读。25.4 万条刷新记录和 33.6 万条从未消费的事件连同索引占据约 445 MiB，空闲页为零，因此单独 VACUUM 无法解决问题。

在一致性备份上清理过期运行记录后，大小降至 206.94 MiB，释放 338.49 MiB（约 62%）。28 张非运行历史表逐行一致，完整性及外键检查通过。实际回收量取决于记录年龄、活动读者及文件碎片。

## API

以下接口只允许管理员，响应不缓存；修改接口还要求当前会话的 CSRF token。

- `GET /api/v1/database`：`running`、`storage`、`result`、`error`、`articleRetention`。
- `POST /api/v1/database/compact`：接受后台任务返回 202；已有任务返回 409。
- `PUT /api/v1/database/article-retention`：`{"enabled":false,"retentionDays":30}`。

`storage` 包含 `databaseBytes`、`walBytes`、`freeBytes`、`entryCount`、`feedCount`、`tables`。`result` 包含前后占用、实际释放字节数、清理刷新记录数量和 WAL 是否已截断。PostgreSQL、MySQL 和内存 SQLite 不提供文件压缩入口。
